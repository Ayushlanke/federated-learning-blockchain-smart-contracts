Cryptographic Security & Tamper Detection

The BC-FL-SRV security layer validates model updates before ledger inclusion. It cryptographically binds model updates to client identities and round numbers, completely preventing unauthorized participants, forged updates, and in-flight parameter modifications.

1. Parameter Byte Flipping

Attacker modifies 100 model parameter values in-flight after the client has signed.

2. Commitment Forgery

Attacker replaces commitment hash with a forged value while attempting to reuse client signature.

3. Unauthorized Client

Unregistered entity generates an Ed25519 keypair and attempts to submit an update.

4. Blockchain Block Tampering

Direct modification of past committed transaction block on a ledger node.

BC-FL-SRV: Verifiable Admission Decisions for Federated Learning

In privacy-preserving federated learning with secure aggregation, the central server deliberately cannot inspect individual client updates. This creates an accountability hole (AG1): the server can claim it admitted 40 honest clients and rejected 10 outliers, but no external party can verify whether that claim is true.

BC-FL-SRV solves this by introducing a rotating committee that inspects bounded evidence and co-signs admission sets into an append-only Merkle transcript, enabling any third-party auditor to verify admission integrity in logarithmic time.

1. Research Subsystem (Admission Verification)

The foundational research verified in E1–E5, G2, and G3:

  • Merkle Transcript: Append-only log providing inclusion proofs and non-equivocation (AG3).
  • Auditor: Evaluates admission rules in O(log n) time without accessing raw weights.
  • Rotating Committee: Deterministic sortition seeded from previous transcript root.
  • Bounded Evidence: Discloses minimal metadata without leaking training inputs.

2. Demonstration Subsystem (Decentralized FL)

The end-to-end interactive training platform built here:

  • Multiple FL Clients: Training PyTorch SmallCNN models locally on non-IID shards.
  • Ed25519 Signatures: Authenticating every update commitment.
  • Distributed Ledger: Multi-node ledger with quorum consensus recording round events.
  • Real Model Inference: Generating a verified global model for Fashion-MNIST classification.
